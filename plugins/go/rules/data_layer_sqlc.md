# Data Layer & SQLC Standards

Persistence rules for Go backend services, enforcing SQLC type-safe code generation, repository adapters, schema boundaries, and multi-tenancy.

---

## 1. Core Data Layer Rules

1. **Repository Encapsulation**: All database access must strictly go through the repository layer (`internal/<domain>/repository`).
2. **Type Safety via SQLC**: Use [SQLC](https://sqlc.dev/) for generating type-safe Go structs and query methods from raw SQL queries.
3. **Parameterized Queries**: Never concatenate strings to build SQL queries. Always use parameterized queries (`$1`, `?`) to prevent SQL injection.
4. **Service Database Isolation**: Each microservice must own its database schema. **Never share databases across services or directly query another service's database tables.**

---

## 2. SQLC Query & Repository Structure

### SQL Query Definition (`sql/queries/users.sql`)

```sql
-- name: GetUserByID :one
SELECT id, email, tenant_id, created_at, updated_at
FROM users
WHERE id = $1 AND tenant_id = $2
LIMIT 1;

-- name: CreateUser :one
INSERT INTO users (id, email, password_hash, tenant_id, created_at, updated_at)
VALUES ($1, $2, $3, $4, NOW(), NOW())
RETURNING id, email, tenant_id, created_at, updated_at;
```

### Repository Implementation Wrapping SQLC

```go
package repository

import (
    "context"
    "database/sql"
    "errors"
    
    "myproject/internal/user/model"
    "myproject/internal/user/repository/db" // Generated by sqlc
)

type PostgresUserRepository struct {
    queries *db.Queries
}

func NewPostgresUserRepository(q *db.Queries) *PostgresUserRepository {
    return &PostgresUserRepository{queries: q}
}

func (r *PostgresUserRepository) GetByID(ctx context.Context, id string, tenantID string) (*model.User, error) {
    row, err := r.queries.GetUserByID(ctx, db.GetUserByIDParams{
        ID:       id,
        TenantID: tenantID,
    })
    if err != nil {
        if errors.Is(err, sql.ErrNoRows) {
            return nil, model.ErrUserNotFound
        }
        return nil, err
    }
    
    return &model.User{
        ID:        row.ID,
        Email:     row.Email,
        TenantID:  row.TenantID,
        CreatedAt: row.CreatedAt,
    }, nil
}
```

## 3. Multi-Tenancy Rules

In multi-tenant environments:

* Extract `tenant_id` from the authenticated request context (injected by auth middleware).
* Pass `tenant_id` into repository operations and **always enforce `WHERE tenant_id = $N`** in all read, update, and delete queries.

```sql
-- ✅ Enforces tenant scoping
UPDATE orders SET status = $1 WHERE id = $2 AND tenant_id = $3;
```

### ❌ Forbidden

```sql
-- ❌ DANGEROUS: Missing tenant isolation
UPDATE orders SET status = $1 WHERE id = $2;
```

---

## 4. Forbidden Data Layer Actions

* ❌ Writing raw SQL strings or invoking DB queries inside HTTP/gRPC handlers.
* ❌ Embedding transaction handling or SQL driver imports directly in the domain service layer.
* ❌ Sharing database connections or cross-joining tables across different microservices.
